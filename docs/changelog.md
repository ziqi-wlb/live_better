## 2026-10-31

### 新增「使用说明」页

详情页上的「收益 / 证据等级 / 性价比」三个数字一直没有解释——用户看到「A」「极高」「大」，不知道各自在说什么、该怎么用。补了一页 `pages/help/help`：

- 这个小程序做什么（767 条建议的离线查阅工具，重点是「不用全做」）
- 先看性价比、再看证据等级（两者回答不同问题，各举一例说明互不影响）
- 性价比 极高 / 高 / 一般，以及它是怎么算出来的
- 证据等级 A / B / C 各自代表什么，以及「A 级不等于因果」
- 收益的口径（换寿命 / 换钱 / 换时间精力 / 换人身自由），不同口径之间不比较
- 收益的量级（大 / 中 / 小）及各口径的具体判定界线
- 成本三项（钱 / 时间 / 毅力）
- 有争议 / 待核实
- 内容来源与许可（CC BY 4.0、不构成专业建议）

**内容照着来源和代码写，不自己编口径**：证据等级的定义取自上游 README；性价比三档是按 `gen_data.py` 里 `roi_of()` 的实际算法反推的（收益档 + 三项成本之和），不是凭印象描述。这点尤其重要——一页讲评分规则的文档，如果和代码里的规则对不上，比没有更糟。

**入口调整过三版**：

1. 最早放在首页底部文档区。但那里原本挤着「用户协议 / 隐私政策 / 意见反馈」，四个链接一行显得杂乱，还把每项挤成了三个字（见下面那条）。
2. 于是恢复首页原样的三个链接。
3. 最终放在**指南库 tab 栏第 5 项**。

| 位置 | 文案 |
|---|---|
| 指南库 tab 栏第 5 项 | 说明 |
| 详情页三个标记下方 | 收益、证据等级、性价比是什么意思？ › |

「说明」tab 点了直接跳说明页，**不走 `onSwitchTab`** ——它不是第四个内容视图，也没有「选中」这回事，所以不参与 `tab-active`。

详情页那个才是真正会被用到的——用户是在对着标记发懵的时候才想查。

> 顺带把 tab 横向内距从 30rpx 收到 22rpx：tab 是内容定宽的，五个各 2 字，收藏 / 清单 同时出现三位数角标时（如 128 / 99）会顶出屏幕 14rpx。全书 767 条，收藏破百完全可能。收到 22rpx 后有 66rpx 余量。

**条数与章节数在页面内动态读取**，不写死，避免重蹈分享图印着旧数字的覆辙。

**图例配色与详情页保持一致**（A 深绿 / B 橄榄 / C 浅灰；极高橙红 / 高琥珀 / 一般浅绿；大 / 中 / 小 青蓝三阶），用户能拿实物对照。

> 排版细节：色标列定为 150rpx。实测最长的「换时间精力」在 132rpx 下只剩 0.5px 余量，换一种字体渲染就会被裁掉。

### 修首页底部链接被挤成每行三个字

加了「使用说明」之后，那一行变成：

```
使用说    ·  用户协    ·  隐私政    ·          意见反馈
明           议           策
```

不是空间不够——容器可用 670rpx，四个链接加分隔点一共约 489rpx。真正的原因是 **Skyline 下 `button` 不按普通 flex item 处理**：`width: auto` 时它按块级铺满整行，把同排的文字挤到只剩三个字的宽度，文字只能折行。右边那一大块空白就是按钮占着的地方。

改法：这一行所有项 `flex: none` + `white-space: nowrap`（不伸缩、不折行），按钮给死宽度 100rpx（四个字 88rpx 有余量），外层加 `flex-wrap: wrap` 兜底——万一将来真放不下，整项换行，也不会再把字拆开。

> 和详情页那三个按钮是同一个病根。Skyline 里凡是有 `button` 参与的 flex 布局，都别指望它按 flex 规则分配宽度。

### 跳转失败不再静默（全站收成一个入口）

`wx.navigateTo` 失败时默认什么都不做。之前全站 7 处跳转里只有 1 处带失败提示，其余 6 处是裸调用——用户点下去毫无反应，只能再点一次。最要命的是 `library.js` 的 `openDetailPage`：它的 `fail` 只做了 `hideLoading()`，不弹提示，而列表点卡片、清单点条目全走它，首次进详情还要下载 1MB 多的分包，失败概率最高的正是这里。

新增 `utils/nav.js`，两个函数：

| 函数 | 用在哪 |
|---|---|
| `navigate(url)` | 说明页、协议页等主包页面 |
| `navigateWithLoading(url)` | 详情页（延迟 200ms 出 loading，失败时收 loading 并 toast） |

现在全项目只剩 `utils/nav.js` 里两处 `wx.navigateTo`，其余页面一律调封装。

### 新增：搜索历史（最近在搜）

搜索框下方列出最近搜过的词，点一下直接填入并搜索，不用再手打一遍。

- 只存在本机（`searchHistory`），不联网、不上传
- 最多留 6 条（「最近在搜」就显示 6 条，两列 3 行），重复的自动提到最前，不产生重复项
- 关键词停稳 300ms 且长度 ≥ 2 才记入 —— 单字太泛，记了也是噪音
- 带「清空」入口

**何时显示**（随后调整过两版）：最初写成「输入框为空就显示」，等于一进指南库就摊着一排历史词——用户还没决定要搜，这像替他做了决定。改成绑 input 的 focus/blur：

| 时机 | 行为 |
|---|---|
| 刚进页面 | 不显示 |
| 点了搜索框（`bindfocus`） | 显示历史 |
| 开始打字 | 收起，让位给搜索结果 |
| 清空输入 | 重新显示 |
| 点历史词 | 填入 + 收起 |
| 失焦 200ms 后 | 收起 |

**踩到的坑**：点历史词时 input 会**先 blur**，如果立刻隐藏面板，这一下点击会落空（面板没了，tap 打不到目标）。所以收起延迟 200ms，并在点历史词时把延迟定时器清掉。

顺带补了 `onUnload` 清理输入防抖 + 延迟收起两个定时器——否则页面销毁后回调仍在跑，小程序会报向不存在的页面 `setData`。

**边界处理**（随后补上）：最初只限制了条数，**没限制单条长度** —— 输入框本身没有长度上限，一条长文本就能占掉几十 KB。现已补齐：

- 单条最长 30 字，超出截断
- 读取时统一清洗：非字符串、空串、重复项一律丢弃，再按 6 条截断（旧版本存过 10 条的，升级后自动收敛到 6 条）
- storage 不是数组（被别的逻辑或用户手动改过）时返回空数组，不把脏数据喂给渲染层
- 写入失败（配额满等）静默忽略，不影响搜索本身

实测覆盖：300 字输入、39 项脏数据、非数组、写入抛异常——都不崩且结果合规。

### 性能：首次进详情页卡顿几秒

线上反馈「首次点击会卡顿几秒」。详情数据按章节拆在两个分包（1.1M / 1.2M），首次进入要下载并解析，而原来的 `preloadRule` 有两个问题：

- **`network: "wifi"`** —— 4G/5G 下**完全不预下载**，首点必然走网络
- 只预下载了 `packageDetail`，**没管 `packageDetail2`** —— 第 12 章以后的条目首点必卡

改法：

- 两个页面的 `network` 都改为 `all`
- 首页预下载 `packageDetail`，指南页预下载 `packageDetail2`（微信限制单页预下载 2M，两个包合计 2.3M 放不下一页，只能分开）
- 两个分包都补上 `name`（`detailA` / `detailB`）—— **`wx.preloadSubpackage` 传的是分包别名，不是 root**，原先传 root 很可能根本没生效
- 首页 `onLoad` 调 `wx.preloadSubpackage({ name: 'detailB' })`，指南页 `onLoad` 调 `detailA`，两个页面合起来覆盖两个包
- 跳转加**延迟 200ms 的 loading**：跳得快不会闪，分包加载慢时用户能看到「加载中」而不是干等

### 详情页三个按钮最终改为固定百分比等宽

第一次只修了 picker 内部宽度（`flex:1` 对它无效），真机上三块还是不等宽。

根因有两层：

1. **`button` 是「受限弹性容器」**——浏览器和小程序都会按内容强制加最小宽度保护，`flex:1` / `flex-basis:0` 在它身上被覆盖，宽度退化成由文字长短决定
2. **项目跑的是 Skyline**（`"renderer": "skyline"` + `glass-easel`），`flex-shrink` 的默认值可能是 0，元素根本不会收缩

改成**不依赖 flex 分配**：三块固定 `width: 31%`，剩下 7% 由 `justify-content: space-between` 分成两段间隙。

顺带把 `button[plain] { border: 0 }` 换成类 `.act-share { border: 1rpx solid }`——Skyline 对 CSS 选择器的支持是子集，不保证支持属性选择器。分享按钮的描边改成显式写在类上，`box-sizing: border-box` 保证描边不额外撑宽。

实测（含模拟 Skyline 的 `flex-shrink: 0`）：三块 103.84 / 103.84 / 103.84，差 **0.00px**，两段间隙均 12px。

### 修详情页「加入清单」按钮比左右宽

中间那个按钮被 `picker` 包了一层，不是 `.actions` 的直接 flex 子元素，`flex: 1` 对它无效，宽度退化成由文字长短决定，于是比「收藏」「分享」宽。改成 `width: 100%` 撑满 picker。

### 同义词扩展（可复用模块 `utils/synonyms.js`）

搜索「炒股」返回 0 条——语料里只有「股票/基金/投资」，2-gram 无法跨越 `{炒股}` 与 `{股票}`（无公共 bigram）。新增同义词词典修复口语问法与语料用词的落差：

- **词典**：38 组同近义词（钱/投资、看病/医保、婚育、维权、诈骗、账号安全、生活习惯、慢病等），每组词互为可匹配项；维护原则是先确认词确实出现在 `data/guides.js` 再收录，避免空转
- **权重**：原词满权重；同义词降权 `SYN_WEIGHT=0.6` 并**按组内距离递减**（`1-(i-1)*0.06`，下限 0.35），所以搜「炒股」时「股票」排在「年化」前面
- **高亮**：`expandTerms()` 把查询词展开为「自身+同义词」，搜「炒股」也能把「股票」「投资」标黄
- **放弃单字回退**：曾尝试「词整体不中时退回单字命中」，实测「存不下钱」返回 368 条、「脱发」129 条无关结果，噪音远大于收益，已移除——宁可返回空并提示换个说法
- 实测：炒股 20、失眠 13（睡眠/作息/午睡）、减肥 11、阳痿 3（勃起）、医保 53、被骗 3；脱发/颈椎/存不下钱 语料无对应内容，返回空态

### 模糊搜索（可复用模块 `utils/search.js`）

搜索从「整串子串匹配」升级为真正的模糊匹配，纯本地、无依赖：

- **多关键词**：空格/逗号/顿号/分号切分，多词之间为「且」，命中越多排越前
- **相关度打分**：标题 12（完全相等再 +8）> 摘要 5 > 章节名 4 > 人群/口径 3 > 模糊命中 1
- **2-gram 相似兜底**：词未精确命中时，用 bigram 覆盖率（阈值 0.6）判断近似
- **两阶段降级**：第一阶段要求每个词都命中；无结果时自动放宽为「命中任一词」并显示提示条「已按相关度显示最相近的条目」（`fuzzyMode`）
- **命中高亮**：`highlight()` 把标题/摘要切成 `{t, h}` 分段数组，卡片用多个 `text` 渲染（`.hit` 琥珀底），避开 rich-text 在 Skyline 的兼容问题
- **片段截取**：`snippet()` 截取命中位置附近的 72 字，避免关键词被长摘要埋掉
- 排序：有关键词时按相关度降序，同分再走原有章节/性价比/证据排序
- 搜索框占位改为「搜『租房 押金』，多个词用空格」提示多词用法
